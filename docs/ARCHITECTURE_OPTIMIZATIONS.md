## 决策与边界

1. 选择按用户目录限制应用实例，维持已有进程内串行写入模型；不引入跨进程多写者协调。
2. 安全文件仍使用 V1 格式。文件替换是提交边界；结果不确定时先限制资源，再由 SafetyCoordinator 核对和恢复。
3. 依赖检查以解析后的模块路径为准；已有运行时 CSP、IPC 校验和网络策略继续承担运行时边界。
4. 先缩短辅助信息预算并复用结果，保持一次返回完整安全目录的接口；不增加第二条目录发布路径。合并任务只在所有调用者离开后取消。
5. 播放协调模块替代界面入口中的播放状态和恢复流程；StreamPlayer 继续拥有 HLS、视频元素、播放会话释放和媒体指标。跨进程准入仍由主进程负责。

## 验证记录

环境：本机 macOS / Apple Silicon，Electron 43.3.0。验证使用隔离目录与生成的视频信号，不读取日常观看数据。

连续播放的生成信号实测：媒体推进约 61 秒、停顿 0 次、停顿时间 0 毫秒、掉帧 0 / 1529。这是本机可重复信号验收，不代表第三方直播源的稳定性。

依赖复核还发现原有打包工具间接依赖 `js-yaml 4.3.1` 的[已知 CPU 消耗问题](https://github.com/nodeca/js-yaml/security/advisories/GHSA-2883-xcg3-v3hh)，已仅更新其锁定补丁版本至 `4.3.2`；官方 npm registry 审计结果为 0 项漏洞。运行时依赖没有升级。

保留的取舍：辅助数据可复用最多 12 小时，整个目录同步仍可能受必需接口等待影响；HLS 分块仍保留超过 500 KB 的构建提示。现有安全状态 V1、目录缓存 V2 和观看记录格式保持兼容。
