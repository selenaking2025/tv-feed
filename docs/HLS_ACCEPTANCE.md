# HLS 兼容性验收

TV Feed 把协议示例与真实电视台分成两组验证，避免把“某条第三方线路今天可播”误写成长期授权或可用性承诺。

## 验收边界

- 协议组运行时从 Apple Developer 示例页和 hls.js 官方测试清单发现测试资产，不在仓库保存播放列表或完整媒体 URL。
- 电视台组只维护频道 ID、电视台官网和人工批准的精确线路主机名。当前清单为 19 个候选频道。
- 实际完整 URL 只从用户本机现有目录缓存中临时匹配，不写入报告或 Git 历史。
- 每个地址都经过 TV Feed 的 DNS 公网校验、固定解析、逐跳重定向复查、HTTPS 与响应大小限制。
- 媒体探测最多读取 64 KiB 范围，不保存节目片段。
- 报告只包含名称、主机名、HLS 结构和错误分类，不包含完整直播 URL。

## 覆盖项目

- 单层媒体清单与 Master Playlist。
- 相对路径与跨主机 CDN 引用。
- MPEG-TS、fMP4、初始化片段和字节范围。
- AES-128 密钥沿同一安全网络通道读取。
- DRM 或非 AES-128 内容保护只识别并拒绝，不尝试绕过。
- 实际 Electron 播放另由隔离用户数据目录的 smoke 验证。

## 本机执行

先关闭失效的代理环境变量，或确保代理可用。然后传入本机目录缓存路径；缓存只被读取，不会复制进仓库：

```sh
npm run verify:hls:acceptance -- --catalog "/path/to/local/catalog-v1.json" --report "/tmp/tv-feed-hls-acceptance.json"
```

直播源会变化、停播或受地域限制。一次通过只证明测试当时的安全通道与该 HLS 结构兼容，不证明后续持续可用，也不构成内容授权结论。
